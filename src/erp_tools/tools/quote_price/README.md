# `price` — 客户报价【列表】查询 / 导出 CSV

> 页面：`/Admin/BaoJia/BJ_KHBJ/Index.aspx?QXID=860&MenuTree=1&LoginUserID=<uid>`
> 用途：按日期/客户/审批状态等条件筛**报价产品行**，导出 CSV。
> MCP 工具名：`erp_price_list`。

⚠ **一行 = 一个报价产品行，不是一张单据**。表单编号形如 `KHBJ261112003-01`，
末尾 `-NN` 是行号；同一张单的多个产品会是多行。定位单行用 `记录ID`（GUID）。

## 命令

```powershell
.\.venv\Scripts\erp.exe price [选项]
```

## 选项

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--from YYYY-MM-DD` | 本月 1 号 | 日期区间起 |
| `--to YYYY-MM-DD` | 今天 | 日期区间止 |
| `--date-type 名称` | `制单日期` | 区间作用于：制单日期(`ZDRQ`) / 交货日期(`KHJHRQ`) / 离厂日期(`LCRQ`) |
| `--key 文本` / `--field 中文名` | 空 | 服务端关键字；字段下拉 28 项（表单编号/客户名称/产品名称/香港单号…） |
| `--key1` / `--field1` | 空 | 第二套关键字 |
| `--filter 键=值` | 空 | **服务端**下拉过滤，可重复，见下表 |
| `--customer` / `--sales` / `--status` | 空 | 等价 `--where 客户名称~X` 等 |
| `--where 表达式` | 空 | 本地多条件过滤，语法与 `erp query` 相同 |
| `--columns a,b,c` | 53 列 + `记录ID` | 只导出指定列（`选择/信息/打印` 三个操作列默认剔除） |
| `--out 路径` | 无 | 导出 CSV（`.jsonl` 结尾则写 JSONL） |
| `--jsonl 路径` | 无 | 额外写一份 JSONL |
| `--limit N` | 不限 | 最多返回 N 行 |
| `--page-size N` | 5000 | 每页行数；不够则用 `btnNext` 续翻 |
| `--max-pages N` | 200 | 翻页安全阀 |
| `--dry-run` | 关 | 只打印条件与命中数，不写文件 |

## `--filter` 支持的键

| 中文别名 | 控件 | 可选值 |
| --- | --- | --- |
| 审批状态 / 审批 | `txtCheck` | 全部 / 未全审批 / 已全审批 / 未审批 |
| 报废状态 / 报废 | `txt_SFBF` | 全部 / 已报废 / 未报废 |
| 确认情况 / 确认 | `txtQDQK` | 全部 / 未确认已审批 / 已确认 |
| 签订单 / 合同 | `txtXKHDD` | 全部 / 已签合同 / 未签合同 |
| 查询方式 | `txtFXCX` | 本单查询 / 分析查询 |
| 客户属性 | `txtKHSX` | 内销 / 外销 / 转厂 |
| 模板 | `txtMBF` | 全部 / 是模板 / 非模板 |
| 预计报价月份 | `txtBetRQ` | 未设置 / 本月 / 二月 / 三月 / 四月 |
| 报价分类 | `txtCFWZ` | 公司意向报价 / 利润高报价 / 不适合公司 / 无意义的更新报价 / 需优化报价 / 目标价太低 |

值可以写**显示文字**也可以写**提交值**（如 `报废状态=未报废` 与 `报废状态=2` 等价）；
写错会报错并列出该下拉的真实选项。

## 示例

```powershell
# 本月全部
erp price --out out\price.csv

# 已全审批 + 未报废
erp price --filter 审批状态=已全审批 --filter 报废状态=未报废 --out out\ok.csv

# 按交货日期看明年的单
erp price --date-type 交货日期 --from 2027-01-01 --to 2027-12-31 --limit 20

# 单号前缀定位（服务端关键字）
erp price --key KHBJ261112003 --field 表单编号 --dry-run
```

### 解析要点（踩过的坑）

- **不是每个报价页都有「选 配 项 目 列 表」**：它夹在「数量明细」和「部件明细」之间，
  表头是 `选配项目/数量/单价/金额` 横向重复 3 组（一行 = 3 个「项目+一档数量」）。
  实测本月 123 行里 **29 行（23.6%）有**，其余 `optionals` 为空列表。
  检测按**表头结构**，不要按标题文字（标题写作 `选 配 项 目 列 表`，字间带空格）。
- 选配项目有两种数据形态，都保留：
  * **整段完全重复**（如【封面】烫金，同样的数量/单价/金额出现两遍）→ 去掉重复档，
    该项上记 `dropped_duplicates`；
  * **同名两条价格曲线交错**（如【产品】0.02mm厚PP空白收缩袋，同一数量两种单价）→
    这是两条报价曲线，页面上没有字段能区分归属，所以留在同一条里（按数量排序后相邻），
    并在该项上记 `同名重复档`。
- 数量明细/部件明细"没有"时：`diagnostics` 会区分「页面本来就没有这段」（正常，如套装单）
  和「页面上有表却没解析到行」（结构变了）。判断存在性同样只看表格结构 ——
  汇总数量那个 span 的 `title` 里永远含「产品数量」，按文字判断会误报。
- `Option=3` 只读页里**表头控件全是 `disabled`**，真正的值在单元格内**没有 name/id 的
  `<INPUT readonly VALUE='...'>`** 上（属性还是大写 `VALUE`）→ 只能按「标签格 → 右邻格」读。
- 一个格子可能同时装 `select` + 辅助 `input`（如 币种 格里塞着 汇率），所以取值顺序是
  **select 选中项 > input 值 > 纯文本**；占位项（`-0-`/`<--请选择-->`）要当空串，
  否则会把整串 option 文字当成值。
- `汇率`/`发票税率`/`折扣率` **没有标签格**，只能按控件名（`txtHL`/`txtFPSL`/`txtZKL`）取。
- 数量明细表**只有第一组**表头写「产品数量」，后面几组写「数量」；判定条件是「首格=产品数量」。
- 表格是**嵌套**的（部件表嵌在数量表里），遍历行必须用
  `tr.find_parent("table") is table` 过滤，否则会把部件表当数量行。
- 空单元格用 `.` 占位，`blank_if_placeholder()` 会归一成空串。
- 产品名称后面跟着 `【 删除】` 按钮文字，要剥掉。
- 页面上那一大堆 `txtBJ*`/`txtKJ*`/`txtDT*` 是产品/部件弹窗编辑器的暂存控件，
  只读页里全是空值，**不要**当成数据源。

## 页面事实（实测 2026-11，账号 2069）
- 56 列：`选择/信息/打印` + 报价状态、有排交期、客户名称、香港单号、产品类型、装订方式、
  产品类别、产品名称、预计报完日期、规格、款数、语言数、最小值/中间值/最大值、单位、总P数、
  客户目标价、单价、版费/印后/纸箱费/台版费/海运费/其他金额/纸张/辅料/印前/印刷单价、金额、
  纸张费用、辅料金额、印前/印刷/印后金额、版费、纸箱费、台版费、海运费、其他金额、业务员、
  制单日期、制单人、审核人、审核日期、备注、表单编号、签订单、存放位置、参数对比、
  来源单号、订单编号、需求产品备注3（`客户名称` 是客户简称，如 `IBL10`）。
- **记录 ID** 在 `ondblclick="OnDBClickOpenData('<ID>','860',3)"`；行内还有
  `showMessagePop('<ID>')` / `IndexPrint('<ID>')` / `OpenInputCPSLZLData('<数量明细ID>', ...)`，
  最后一个不是主记录 ID。
- 末尾有「合计」行；查不到时返回「一行全空占位」。两者都由 `tools/gridlist.py` 丢掉。
- `txtEvenPageDataSize=5000` 可一页取全；翻页是 `__doPostBack('btnNext','')`。
- **搜索按钮是 `input type=submit name=btn_Search value=搜索`**：必须回发 name/value，
  只发 `btn_Search.x/.y`（image 按钮的写法）会让 ERP 走默认绑定，**所有查询条件被忽略**
  （表现为「每次都是同样的行数」）。`button_payload()` 会从页面读真实 type/value。
- 日期区间只在真正触发 `btn_Search_Click` 后生效；不带按钮时页面默认列表与搜索结果不同
  （实测同一天：默认 89 行 / 显式搜索后本月 123 行）。
